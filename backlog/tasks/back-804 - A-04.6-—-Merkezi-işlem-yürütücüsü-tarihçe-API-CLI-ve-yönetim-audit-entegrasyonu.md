## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Ortak Core yazıcı ile server.sqlite kaydı, mevcut doğrulanmış kullanıcı/proje sınırından bağlanmalı; insan kayıp işlemi ve kurtarma durumunu kanonik CLI ile inceleyebilmeli. Yönetim değişikliğiyle audit aynı DB transaction'ında kalmalı.

Öneri: yeni mutation-types.ts ortak DTO/header/hata sözleşmesi ve mutations.ts tek yaşam döngüsü yürütücüsü; ilk envanter, başlangıç kurtarması, proje bazlı sıra ve writeState. Parola taşımayan yönetim yazılarında anahtar/revision; parola taşıyanlarda A-04.1 kapsam kararına göre güvenli audit.

Yeni önerilen yüzey: GET /api/projects/:id/history, /operations/:operationId; admin history ve operation GET. CLI server history list, operation view, recovery list/view ve karar kabul edilirse fingerprint'li recovery resolve --accept-observed. Mevcut GET proje yanıtına writeState; mevcut DTO'lara revision. Tarihçe yazma/silme veya yeni görev CRUD API'si eklenmez. Önerilen endpoint ve alan detayları doc-6 bölüm 4'tedir.

Sahiplik: src/server/{central,auth-store,project-store}.ts, yeni {mutations,mutation-types}.ts, src/commands/server.ts, README ve central/CLI/admin testleri. database/mutation-store A-04.2; index/Core/FS A-04.3/4; bütün web A-04.5. Ana ajan ortak tipleri önce yerleştirir. Başlama A-04.1; kapanış A-04.2/3/4/5 entegrasyonuna bağlıdır. Yönetim sırları olay veya request hash'e girmez; yerel CLI operatörü doğrulanmış web kullanıcısı gibi gösterilmez.
