## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
İki kişinin aynı kaydı düzenlemesinde eski içerik yeni kaydı ezmemeli; ağ yanıtı kaybolduğunda kullanıcı aynı işi ikinci kez oluşturmamalı. Mevcut taslak/oturum koruması, yeni revision semantiğini doğru taşımak için kullanılacak.

Mevcut text/plain karar save, arşiv, draft, inline AC/DoD/comment, pano drag/drop, milestone/config ve yönetim formlarının tamamı envanterle bağlanır. Yeni tam geçmiş ekranı A-06'dır.

A-04.1 kontratıyla test doubles üzerinde başlanabilir; gerçek birleşmiş API ile doğrulanmadan kapanmaz. Aynı/farklı hesap ve kirli gezinme mevcut kalıpları korunur.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Audit every existing web mutation and its live-refresh/auth ownership path, then bind the accepted doc-6 contract to shared web request helpers and central-only metadata. Preserve local browser calls and decision text/plain.
2. Carry recordKey/revision and collection/config snapshots through search, detail, draft, archive, board and forms. Keep each editor's original revision and dirty text through WS/session refresh; expose conflict and recovery actions without auto-overwrite.
3. Attach one UUID Idempotency-Key per logical write plus If-Match or expectedRevisions where required; on an uncertain response query the authorized operation with the same key and allow an explicit same-key retry. Distinguish all machine-readable error codes while preserving existing ApiError/HttpError consumers.
4. Wire task/doc/decision, inline, lifecycle, board, cleanup/repair, milestone/config and password-free admin paths. Keep permission controls separate from project writeState, account-scope pending operations, and retain current unsaved-navigation behavior.
5. Add focused DOM/API tests for dirty-refresh baseline, conflict/error classification, board rollback, uncertain operation result and auth isolation. Integrate against the actual backend contract, run scoped Bun, type and Biome checks, then pass Chromium scenarios to BACK-805 acceptance. Review and simplify duplicated request/UI logic before finalization.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Central browser writes now use one owner-scoped UUID per logical request, durable operation lookup on uncertain outcomes, and an explicit same-key retry. A 401, 403, 404, or 503 after an intent can remain uncertain. Auth, password and preview requests remain outside replay. The shared error path distinguishes server codes, with legacy 409 fallback only when code is absent. Local browser requests omit central preconditions.

Task, document and decision editors retain the starting record revision and dirty text through live refresh and same-account session renewal. Successful inline task/comment edits advance their own pinned revision; title blur in full edit waits for Save, and failed optimistic sidebar edits roll back. Decision updates still send text/plain. Search and board use the collection header from the same response, including the revision returned by a successful own move or reorder. Other central task, draft, lifecycle, milestone, config, cleanup and password-free management writes carry their approved If-Match, expectedRevisions or preview fingerprint. Recovery writeState stays separate from permissions. Two small notices expose conflict, operation status, manual retry and recovery actions without automatically replaying a write.
