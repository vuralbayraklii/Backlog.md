## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->

Keep the first secret in component memory only and clear it on dismissal or account change.
2. Surface the approved observation DTO in the existing Projects cards and project-wide status area. Keep observation separate from A-04 recovery/writeState and from granted permissions; derive one writesAvailable gate for all existing web mutation controls. Refresh status from project detail, live WS metadata and project-list focus/polling without remounting dirty editors.
3. Add focused DOM/API tests for user/project grant construction, one-time secret visibility, uncertain create metadata without secret, revoke If-Match/UUID, degraded-to-ready control changes, recovery separation, session/dirty draft and existing theme/layout behavior. Run scoped Bun, types, default Biome and changed-TSX baseline comparison, then join native Chromium acceptance once backend API is ready.
